# MOSS

ESP32-S3 Wi-Fi 板型，基于 WiFi 面包板实现，接线对应嘉立创EDA工程
`moss_pcb_old → INMP441版本 → P1`，其中 OLED 引脚以已确认的实物接线为准。

## 引脚

| 模块 | 信号 | GPIO |
| --- | --- | --- |
| INMP441 | SD | 4 |
| INMP441 | SCK | 5 |
| INMP441 | WS | 6 |
| MAX98357A | DIN | 7 |
| MAX98357A | BCLK | 15 |
| MAX98357A | LRC | 16 |
| OLED | SDA | 1 |
| OLED | SCL | 2 |
| BOOT | 按键，低电平有效 | 0 |
| 俯仰 ULN2003 | IN1 / IN2 / IN3 / IN4 | 13 / 14 / 21 / 46 |
| 左右 ULN2003 | IN1 / IN2 / IN3 / IN4 | 42 / 41 / 40 / 39 |
| 五路普通流水灯 | 第1～5路，高电平点亮 | 8 / 3 / 9 / 10 / 11 |
| 眼部呼吸灯 | PWM，高电平点亮 | 12 |

原理图中三个模块均使用 3V3/GND，INMP441 的 L/R 接 GND；
MAX98357A 的 SD 接 3V3、GAIN 接 GND，均不由软件 GPIO 控制。

OLED 暂按当前工程配置使用 SSD1306 128×64，I2C 地址为 `0x3C`，
镜像方向沿用面包板配置。用户已确认屏幕能够点亮显示。

BOOT 在启动阶段点击进入配网，其余状态点击切换对话。
初始化两轴电机和灯光模块，上电不自动运动，眼灯和流水灯默认熄灭。
暂不初始化红外、触摸按键、音量按键或示例灯控制。

## 电机与 MCP

硬件为两组 24BYJ48（1:64）+ ULN2003，接线沿用旧 MOSS。
GPIO 接驱动板 IN1～IN4，驱动板按电机额定电压供电，并与 ESP32 共地。
引脚和参数集中在 `config.h`；`moss_motor.h/.cc` 负责运动，
`moss_motor_tools.cc` 负责注册工具，由 `MossBoard::InitializeTools()` 在初始化成功后调用。
不修改公共业务层，不对其他板型注册电机工具。

| MCP 工具 | 参数 | 行为 |
| --- | --- | --- |
| `self.motor.control` | `motor`: `pitch`/`yaw`；`angle`: -90～90 整数 | 接受相对转动命令；0 为不运动 |
| `self.motor.stop` | `motor`: `pitch`/`yaw` | 停止该轴、清空队列并关闭励磁 |
| `self.motor.get_status` | 无 | 查询两轴运动/励磁、排队数量、剩余半步、已输出半步计数和 GPIO 错误 |

方向沿用旧代码：俯仰正角度向下、负角度向上；左右正角度向右、负角度向左。
相序使用八拍，旧代码的 512 组/圈展开为 4096 半步/圈，每拍保持 10ms，
90° 理论运动时间约 10.24 秒。方向、每圈半步数和实际角度都需要实物校准。

同一固定任务调度两轴，每轴最多 4 条待执行命令，同轴按 FIFO 串行，两轴可同时运动。
队列满时拒绝新命令；控制工具返回“命令已接受”，不代表动作已完成。
结束后关闭励磁，不持续保持扭矩；停止不会中断另一轴。
GPIO 出错会取消该轴待执行动作，检查状态后可用停止工具尝试恢复关闭状态。

本实现没有归零、位置反馈或机械限位，单次 ±90° 只是命令范围，不是机械安全行程。
`executed_half_steps` 仅是有符号相序输出计数，不能当作实际位置或绝对角度。
首次验证应先用小角度分别确认两轴方向和行程。初始化失败时保留语音/显示功能，不注册电机工具。

模拟硬件验证：`python -m unittest scripts.tests.test_moss_motor -v`。
它执行真实电机控制代码，检查相序、双轴调度、队列、停止、步数换算与失败处理，不连接实际电机。

## 流水灯、眼灯与 MCP

接线沿用参考项目 `软件/moss-xiaozhi`：五路流水灯 GPIO 依次为 8、3、9、10、11，
眼灯为 GPIO12。流水灯是五路普通开关输出，不是 WS2812；两类灯均按高电平点亮。
引脚控制应通过匹配实物的限流/驱动电路，不可将大电流灯直接接到 GPIO。

`moss_lights.h/.cc` 负责 GPIO、PWM 和一个固定后台任务；
`moss_light_tools.cc` 负责 MCP 注册。由板级 `InitializeTools()` 初始化后注册，
不修改公共业务层，电机初始化失败也不影响灯光初始化。
灯光模块初始化失败则不注册两个灯光工具，保留电机、语音和显示功能。

| MCP 工具 | 参数 | 行为 |
| --- | --- | --- |
| `self.lamp_bar.control` | `action`: `start_flow` / `stop_flow` / `get_status` | 开始流水、停止并熄灭、查询状态 |
| `self.lamp_eye.control` | `action`: `turn_on` / `turn_off` / `start_breathing` / `pause_breathing` / `resume_breathing` / `stop_breathing` / `get_status` | 常亮、关闭、呼吸、暂停、恢复、停止并熄灭、查询状态 |

流水沿用旧项目的五组亮灭图案，阶段时长为 110/100/90/100/130ms，一轮约 530ms。
眼灯 PWM 为 5kHz、13位（0～8191），每20ms增减100，完整呼吸约3.28秒。
使用 LEDC timer 1 / channel 1，避开公共背光使用的 timer 0 / channel 0。
灯效任务以10ms间隔调度，实际节奏受任务调度延迟影响。

常亮、关闭和呼吸模式互斥；暂停保持当前亮度，恢复沿原方向继续。
恢复仅接受已暂停状态；停止或关灯取消呼吸，返回后旧动画不会重新点亮。
两种灯效可以同时运行，重复启动不会反复创建任务。
状态返回软件输出值和最后一次错误，不是实际亮度反馈；输出错误时停止对应灯效并尽力熄灭。
检查接线后可再次发出控制命令重试。当前不自动跟随聆听、思考或说话状态。

模拟硬件验证：`python -m unittest scripts.tests.test_moss_lights -v`。
实际灯效、引脚顺序和亮灭极性仍需烧录后验证。

## 编译

初始化 ESP-IDF 环境后，在仓库根目录执行：

```sh
python scripts/build.py moss --name moss --language zh-CN
```

使用项目 ESP32-S3 默认的 16MB Flash、`partitions/v2/16m.csv` 分区表和
八线 PSRAM 配置；烧录前确认主控模组与之匹配。
固件板型与变体名称均为 `moss`，具有独立的 OTA 身份。

手动配置时，在 `Xiaozhi Assistant → Board Type` 选择 MOSS，
并将 OLED 选为 SSD1306 128×64。

编译通过后仍需在实物验证录音、唤醒、播放、OLED 显示和 BOOT 配网。

## MOSS 显示

屏幕初始化后先播放已确认的 128×64 点阵开机动画，再进入日志界面。
总时长固定为 6 秒：保留前 5 秒原动画流程，结尾额外停留 1 秒展示完整画面。
`moss_display.h` 的 `kBootDurationMs = 6000` 从首次刷新启动帧后计时；
使用 LVGL 定时器切换页面，不阻塞联网和音频启动。启动期间收到的消息会缓存。

主界面用 `U:`、`M:`、`>` 区分用户、助手和系统消息，自动换行并向上滚动。
最多保存 16 条记录，每条最多 512 字节（过长内容按 UTF-8 字符边界截断并加省略号）。
公共业务清空当前字幕时保留终端历史；移除临时消息时只删除最近一条匹配内容。
顶部为固定的 16px 状态栏：左侧显示实际 Wi-Fi 图标，右侧每 200ms 刷新设备状态、
等待计时与光标。下方 48px 日志区使用 12px 行高，可显示 4 行，长消息自动换行。
通知短暂替换状态文字，并保存在日志中；不打印虚构的思考过程，也不显示大表情。
当前没有电池采样，暂不显示电量图标。

MOSS 使用独立紧凑字库 `assets/console_font.h`，由上游现有 16px 行高字库缩放生成，
不修改公共显示类或其他板型。对话补充字形也会缩放，以免中文撑高日志行。
重新生成字库时执行（需要 Pillow 和已安装的 xiaozhi-fonts 组件）：

```sh
python main/boards/moss/assets/generate_console_font.py
```

确认后的点阵 GIF 保存在 `assets/boot.gif`，已生成的 `assets/boot_animation.h` 直接随固件编译，
不依赖外部资源目录。替换图片后，在仓库根目录运行（需要 Pillow）：

```sh
python main/boards/moss/assets/generate_boot_animation.py
```

生成器逐帧保留 GIF 的像素和时序，检查分辨率为 128×64、总时长为 6000ms。
当前共 115 帧，内置像素数据约 116KiB，不需要运行时解码 GIF 或 MP4。
播放按实际经过时间选择帧，显示较慢时跳过过期帧，避免动画越播越长。
底部小字受分辨率限制可能无法辨认。替换动画后需重新生成资源、编译并烧录。
